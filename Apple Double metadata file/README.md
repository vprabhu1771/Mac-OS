### 💡 Why This Happens

The `._` prefix indicates a resource fork file, which is a legacy macOS feature used to store metadata when transferring files to file systems that don't natively support it (like the SSD volume in your path). These files often get created when you copy the project folder to an external drive or when tools like zip/unzip are involved.

Because they are hidden and don't have valid source code content, Xcode's compiler chokes on them when it tries to treat them as header files. Cleaning the `build/` directory ensures these temporary, corrupted files are removed and freshly generated during the next build.

### ✅ If the Problem Reoccurs

If these files keep appearing (perhaps due to a sync tool or external drive format), you can use the `dot_clean` utility to strip them from your source tree without deleting your actual code:

```bash
dot_clean /Volumes/SSD/Pushpa/Taxi-app-live/passenger-app
```

Then run the clean and build steps again.
### Why `dot_clean` Didn't Work

The `dot_clean` utility is designed to **merge** AppleDouble files back into their parent files, not necessarily delete them. When the parent file is a source code file that gets regenerated by Swift Package Manager during each build, the `._` metadata file returns immediately after cleanup. You need to either delete the files after the packages are resolved but before Xcode compiles, or prevent them from being created in the first place.
